# AI_RPA_CALL_CENTER

생성형 AI·RPA 기반 콜센터 인공지능 비서. 통화 녹취 파일을 넣으면 문의 유형 분류, 요약, 조치 정리, DB 저장, 엑셀·웹 대시보드 갱신까지 자동으로 끝나게 한다.

## 처리 흐름

```
음성 폴더 ─▶ ③ 봇(STT → 마스킹 → 분류·요약) ─▶ ① 서버 저장 ─▶ ② 웹 대시보드
                                  │
                                  └─▶ Orchestrator 큐(신호) ─▶ ④ 봇 ─▶ 4시트 엑셀
```

- 웹에서 음성을 올려 처리하는 흐름(흐름 B)도 있다. 자세한 순서는 통합본 4장.
- 웹과 엑셀은 완료(`DONE`)된 통화만 세고, 같은 지표 정의를 쓴다(통합본 8장).

## 폴더

| 폴더 | 파트 | 담당 | 내용 |
|---|---|---|---|
| `backend/` | ① 백엔드 / DB / 서버 | 범수, 민철 | FastAPI 서버, PostgreSQL, 음성 스토리지, Orchestrator 연동 |
| `frontend/` | ② 프론트엔드 / 챗봇 | 수창, 성진 | React 웹 대시보드, 챗봇 화면 |
| `rpa-genai-stt/` | ③ UiPath GenAI·STT | 민영 | STT, 마스킹, 분류·요약, 서버 저장, 큐 추가 |
| `rpa-report/` | ④ UiPath RPA 코어·보고서 | 주영 | 큐 신호를 받아 4시트 엑셀을 만드는 봇, 엑셀 템플릿 |
| `docs/` | 전체 | 주영(통합본) | 통합 제품요구사항정의서와 각 파트 설계서 |

각 파트 폴더에는 지금 README와 CLAUDE.md만 있다. 코드와 워크플로우는 담당자가 자기 설계서의 구조대로 채운다.

## 먼저 읽을 문서

1. `docs/제품요구사항정의서_v1.7.md`: 네 파트의 요구사항, 데이터 계약(7장), 지표 정의(8장), 남은 항목(11장)
2. 자기 파트의 설계서: `docs/README.md`에 목록이 있다.
3. 자기 파트 폴더의 `README.md`

## 작업 규칙 (제안)

팀이 정하면 이 절을 고친다.

- 자기 파트 폴더 안에서 작업한다. 다른 파트 폴더를 고쳐야 하면 담당자와 먼저 이야기한다.
- 파트 사이의 약속(필드 이름, 큐 항목, 유형 값, 지표 정의)을 바꾸려면 통합본을 먼저 고치고 알린다.
- 문서를 고치면 파일 이름의 버전을 올린다(`_v1`, `_v2`). 예전 버전은 저장소에 두지 않는다.

## 올리지 않는 것

이 저장소는 공개 상태다. 아래는 커밋하지 않는다. `.gitignore`에도 넣어 두었다.

- 비밀값: `.env`, API 키, CLOVA 키, Orchestrator 외부 앱의 Secret
- 음성 파일(wav, mp3, m4a)과 실제 상담 녹취
- 봇이 만든 결과물: STT 응답 원본, 결과 JSON, `콜센터_엑셀_최신.xlsx`
- 마스킹하지 않은 전화번호나 이름이 들어간 파일

## Claude Code를 쓸 때

루트의 `CLAUDE.md`에 공통 규칙이, 각 파트 폴더의 `CLAUDE.md`에 그 파트의 규칙이 있다. 파트 폴더에서 작업하면 두 파일이 함께 적용된다.
