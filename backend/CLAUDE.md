# backend 지침 (초안)

담당자(범수, 민철)가 확인하고 고친다. 아래는 `docs/PRD_1_백엔드_v3.md`와 `docs/설계서_1_백엔드_v2.pdf`에서 옮긴 규칙이다. 공통 규칙은 루트의 `CLAUDE.md`에 있다.

## 참고할 곳

- 요구사항과 확인 방법: `docs/PRD_1_백엔드_v3.md` 4절
- API 요청·응답 예시: `docs/설계서_1_백엔드_v2.pdf` 5장
- 환경변수: PRD 9절, 설계서 7.2
- 완료 기준: PRD 11절(인수 테스트 26개)

## 규칙

- JSON 키 이름은 DB 컬럼 이름과 같다. 항목 이름을 바꾸는 일은 `schema.sql`과 설계서를 함께 고칠 때만 한다.
- API 1~8의 요청·응답 형식은 유지하고 항목만 추가한다. 다른 파트가 이미 쓰고 있다.
- 오류는 `{"error": 코드, "message": 한글}` 형식으로 통일한다. FastAPI의 기본 422도 이 형식으로 바꾼다.
- 모든 시각은 `+09:00`으로 돌려준다. `called_at`에 시간대가 없으면 422다.
- `/api/calls/export`는 `/api/calls/{call_id}`보다 먼저 등록한다. 순서가 반대면 404가 된다.
- 통계는 완료(`DONE`)된 통화만 센다. 유형별 집계는 0건이어도 5개를 고정 순서로 돌려준다.
- 상태 전이는 DB 조건으로 막고, 허용되지 않은 전이는 409(`INVALID_STATE`)로 답한다.
- 챗봇은 조회 전용이다. 질문으로 SQL을 만들지 않고, 통화를 직접 수정·삭제하지 않는다.
- 모든 값은 바인딩 파라미터로 넣는다. 정렬·조건 이름은 허용 목록에서만 고른다.
- 비밀값은 환경변수로만 읽는다. `.env`는 커밋하지 않고 `.env.example`만 둔다.
- 로그, 응답, 오류 메시지에 대화 원문, 전화번호, 비밀값을 쓰지 않는다.
- 음성 파일은 정적 경로로 공개하지 않는다. 사용자 파일 이름을 저장 경로에 쓰지 않는다.
