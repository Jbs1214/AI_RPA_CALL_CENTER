## 1. 한눈에 보기

```
③ 봇 ──(서버 저장)──▶ 서버(①) ◀──(GET /api/calls, 1분마다)── ④ 봇
                                                              │
                                                              ▼
                                                 콜센터_엑셀_최신.xlsx (4시트)
```

- ④ 봇은 서버에 저장하지 않는다. 읽기만 한다.
- ③ 봇과 주고받는 데이터는 없다. Orchestrator 시간 트리거가 1분마다 ④ 봇을 시작하고, 엑셀에 쓰는 값은 전부 서버 목록에서 받는다.
- 엑셀은 매번 완료 통화 전체로 다시 만든다. 그래서 웹에서 고치거나 지운 내용도 다음 실행 때 반영된다.

| 접점 | 상대 | 주고받는 것 |
|---|---|---|
| 시간 트리거 | Orchestrator | 1분마다 ④ 프로세스를 시작한다. ③ 민영과는 주고받는 것이 없다. |
| 목록 API | ① 범수, 민철 | `GET /api/calls?status=DONE&include_transcript=true&size=200` |
| Asset | ③ 민영, ① | `BACKEND_BASE_URL`, `BACKEND_API_KEY`. ④가 만들고 값은 ①에게 받는다. ③과 같이 쓴다. |
| 엑셀 파일 | 팀 전체 | `콜센터_엑셀_최신.xlsx`를 직접 전달한다. 웹에서는 받지 않는다. |
| 숫자 대조 | ② 수창 | 웹 카드 6개와 엑셀 대시보드 6개가 같은지(화 12:00) |

**엑셀 파일은 두 종류다.** 이름과 내용이 달라 시연 때 섞이지 않게 한다.

| 파일 | 만드는 곳 | 내용 | 받는 방법 |
|---|---|---|---|
| `콜센터_통화목록_YYYYMMDD.xlsx` | 서버(①, API 7) | 12열 통화 목록 한 시트. 웹의 검색 조건이 적용된다. | 웹의 "엑셀 다운로드" 버튼 |
| `콜센터_엑셀_최신.xlsx` | ④ 봇 | 대시보드·요약·통화 대장·안내 4시트. 완료 통화 전체 | ④가 직접 전달 |

두 파일의 통화 대장 12열은 열 순서와 변환 규칙(한국 시간 날짜, `Y`/`N`, 32,000자)이 같다. 조건 없이 받은 서버 파일과 ④ 엑셀의 통화 대장은 행 수가 같아야 한다(seed 기준 머리글을 빼고 14행). 화 12:00에 범수와 대조한다.

## 3. 처리 흐름

| 순서 | 하는 일 | 실패하면 |
|---|---|---|
| 1 | Asset에서 서버 주소와 API 키를 읽는다. | 예외가 나서 Job이 실패(Faulted)로 끝난다. |
| 2 | 스크립트를 실행한다. 스크립트가 설정 파일(템플릿과 출력 경로, 재시도 횟수)을 읽는다. | 스크립트를 시작하지 못하면 종료 코드 1 |
| 3 | 서버 목록을 받는다. `page=1`부터 시작해 받은 건수가 응답의 `total`에 이를 때까지 `page`를 올린다. | 5초 간격으로 3회 재시도. 그래도 안 되면 5번으로 가지 않고 종료 코드 1 |
| 4 | 목록을 통화일시 오름차순으로 정렬한다(오래된 통화가 위). | 해당 없음 |
| 5 | 템플릿을 복사해 통화 대장을 다시 쓴다(6장). 요약 시트는 건드리지 않는다. 목록과 차트는 템플릿의 수식이 따라온다(7장). | 임시 파일을 지우고 기존 `콜센터_엑셀_최신.xlsx`는 그대로 둔다. 종료 코드 1 |
| 6 | `콜센터_엑셀_최신.xlsx`로 저장한다. | 파일이 열려 있어 못 쓰면 `콜센터_엑셀_최신_시각.xlsx`로 저장하고 경고 로그 |
| 7 | 스크립트의 로그(건수, 관리번호)를 남긴다. 종료 코드가 0이 아니면 예외를 던진다. | Job이 실패(Faulted)로 끝난다. |

1번과 7번은 `Main.xaml`이, 2~6번은 `build_report.ps1`이 한다(10장).

매번 완료 통화 전체로 다시 만든다. 한 번 실패해도 다음 실행 때 전체를 다시 받으므로 빠지는 통화가 없다. 웹에서 수정하거나 삭제한 내용도 다음 실행 때 반영된다.

**바뀐 것이 없어도 다시 쓴다.** 서버 목록이 그대로여도 엑셀 파일을 새로 저장한다. 엑셀을 열어 두면 실행할 때마다 날짜시각이 붙은 파일이 생기므로, 볼 때는 복사본을 열거나 시간 트리거를 잠깐 끈다.

### 실행 방식

| 방식 | 내용 | 언제 |
|---|---|---|
| 시간 트리거 | Orchestrator가 1분마다 무인 실행으로 시작한다. 봇 PC가 켜져 있고 로그인되어 있어야 한다. | 기본 방식. 11/24 15:38부터 돌고 있다. |
| 직접 실행 | Studio, Assistant, Orchestrator의 Start Job으로 실행한다. | 바로 반영해야 할 때, 시간 트리거를 꺼 둔 때 |

무인 실행 자리(런타임)가 1개다. ③의 Job 시작을 시험하거나 여러 건을 연달아 돌릴 때는 시간 트리거를 잠깐 끈다.

### 인자와 설정값

| 이름 | 종류 | 기본값 | 뜻 |
|---|---|---|---|
| 입력 인자 | 없음 | — | `in_ForceRefresh`는 v7에서 없앴다. |
| `TemplatePath` | 설정 | `templates/콜센터_엑셀_템플릿_v3.xlsx` | 엑셀 템플릿 파일 경로 |
| `OutputPath` | 설정 | `output/콜센터_엑셀_최신.xlsx` | `콜센터_엑셀_최신.xlsx`를 둘 경로 |
| `PageSize` | 설정 | 200 | 서버가 허용하는 최대값 |
| `MaxRows` | 설정 | 999 | 요약 시트 수식이 세는 한도 |
| `RetryCount`, `RetryIntervalSec` | 설정 | 3, 5 | 서버 호출 재시도. ③과 같은 값 |

경로와 이름은 워크플로우에 직접 쓰지 않고 설정 파일이나 Asset에 둔다. 설정 파일은 `rpa-report/config.json`이다(`config.example.json`을 복사해 만든다). 상대 경로는 설정 파일이 있는 폴더가 기준이다.

## 4. 받는 데이터

### 4.1 큐 항목 (삭제)

v7에서 없앴다. ③ 봇에게서 받는 데이터는 없다. 절 번호는 다시 매기지 않는다.

### 4.2 서버 목록 (① → ④)

요청: `GET {BACKEND_BASE_URL}/api/calls?status=DONE&include_transcript=true&size=200&page=1`

| 응답 항목 | 쓰임 |
|---|---|
| `total` | 전체 건수. 받은 건수가 이 값이 될 때까지 `page`를 올린다. |
| `items[]` | 통화 목록. 최신순으로 온다. |

`items`의 항목 가운데 엑셀에 쓰는 것은 12개다(6장). `file_hash`, `status`, `retry_count`, `audio_available`, `job_state`, `created_at`, `updated_at`은 쓰지 않는다.

서버는 이 호출에서 API 키를 확인하지 않는다. 그래도 ③과 같게 `X-API-Key` 헤더에 Asset `BACKEND_API_KEY` 값을 붙인다. 서버는 필요 없는 API에 붙어 온 헤더를 무시하고, 나중에 키를 켜도 워크플로우를 고치지 않아도 된다.

| 응답 | 처리 |
|---|---|
| 200 | 정상 |
| 연결 실패, 5xx | 5초 간격으로 3회 재시도 |
| 422 | 요청이 잘못된 것이므로 재시도하지 않고 종료. 오류 로그 |
| `total`이 999보다 크다 | 최신 999건만 쓰고 경고 로그 |

## 5. 원본 템플릿의 구조

원본 `콜센터_엑셀_최종본_MVP.xlsx`를 열어 확인한 내용이다. 봇이 쓰는 템플릿 v3은 여기서 요약 시트의 20행 아래와 차트 범위만 다르다(7장). 대시보드, 요약 시트의 지표와 유형별 표, 통화 대장, 안내 시트의 구성은 같다.

| 시트 | 내용 |
|---|---|
| 대시보드 | 4행에 지표 이름 6개, 5행에 값(`=요약!B3`~`B8`). 차트 4개 |
| 요약 | 통화 대장을 세는 수식. 범위는 모두 `$2:$1000` 고정 |
| 통화 대장 | 1행 머리글, 2행부터 데이터. 표 이름 `tblCalls`(지금 범위 `A1:L15`, 14건) |
| 안내 | 파일 사용법 |

**통화 대장 시트**

| 항목 | 내용 |
|---|---|
| 틀 고정 | `B2` |
| B열 표시 형식 | `yyyy-mm-dd hh:mm` (날짜 값) |
| 목록 제한 | F열은 유형 5개, I열과 J열은 `Y`/`N` (`2:1000`행) |
| 조건부 서식 | J열이 `Y`면 그 행 전체가 노란색, I열이 `Y`면 글자 색 변경 |
| L열 | 숨김 |

**요약 시트**

| 블록 | 위치 | 이름 칸 | 수식이 세는 것 |
|---|---|---|---|
| 지표 6개 | `A3:B8` | 고정 | 분석된 통화, 후속조치 필요, 검토 필요, 불만 통화, 불만 비율, 가장 많은 유형 |

## 6. 통화 대장 쓰기 규칙

| 열 | 머리글 | 서버 항목 | 바꾸는 규칙 |
|---|---|---|---|
| A | 관리번호 | `call_id` | 그대로 |
| B | 통화일시 | `called_at` | 한국 시간으로 바꾸고 시간대 정보를 뗀 **날짜 값**으로 쓴다. 문자열로 쓰면 일자별 집계가 0이 된다. |
| C | 담당자 | `agent_name` | 그대로. `미확인`도 그대로 쓴다. |
| D | 고객사 | `customer_company` | 그대로. `null`이면 빈칸 |
| E | 연락처 | `customer_phone` | 그대로. `null`이면 빈칸 |
| F | 유형 | `category` | 그대로(5개 값) |
| G | 고객 질문 요지 | `customer_question` | 그대로 |
| H | 담당자 조치 내역 | `action_taken` | 그대로 |
| I | 후속조치 | `follow_up_needed` | `true`는 `Y`, `false`는 `N` |
| J | AI 결과 검토 필요 | `needs_review` | `true`는 `Y`, `false`는 `N` |
| K | 녹취 파일명 | `source_filename` | 그대로 |
| L | 통화 내용(숨김) | `transcript` | 32,000자에서 자른다. `null`이면 빈칸 |

쓰는 순서

1. 템플릿을 임시 파일로 복사한다. 템플릿 원본은 고치지 않는다.
2. `A2:L1000`의 **값만** 지운다. 시트나 행을 지우면 요약 수식, 목록 제한, 조건부 서식이 깨진다.
3. 정렬한 목록을 `A2`부터 쓴다.
4. 표 `tblCalls`의 범위를 `A1:L(건수+1)`로 맞춘다. 슬라이서와 필터가 전체 행에 걸리게 하기 위해서다. 방법은 구현 때 확인한다.
5. 저장한다. 요약 시트와 대시보드에는 쓰지 않는다.

**엑셀 프로그램으로 여는 활동을 쓴다.** 파일을 새로 만들어 내는 방식은 차트와 슬라이서를 잃을 수 있다. 봇 PC에 엑셀이 설치되어 있어야 한다.

## 7. 템플릿 v3: 요약 시트의 목록과 차트

### 원본의 문제

원본은 요약 시트에 담당자 3명, 날짜 4개, 고객사 5곳이 고정 값으로 들어 있고 차트 범위도 고정이다. 새 담당자, 새 날짜, 새 고객사가 집계와 차트에서 빠진다.

| 넣은 데이터 | 분석된 통화 | 담당자별 합 | 일자별 합 | 고객사별 합 |
|---|---|---|---|---|
| 원본 템플릿, seed 14건 + 경계 사례 6건 | 20 | **18** | **14** | **18** |
| 템플릿 v3, 같은 데이터 | 20 | 20 | 20 | 20 |

### 바꾼 것

세 목록을 통화 대장에서 수식으로 뽑는다. 봇은 통화 대장만 쓰면 된다.

| 블록 | 위치 | 보여 주는 것 | 순서 |
|---|---|---|---|
| 담당자 | `A20:D30` (10행) | 통화 대장에 나온 담당자 | 통화가 많은 순. 같으면 통화 대장에 먼저 나온 순 |
| 통화일 | `A33:G47` (14행) | 통화가 있는 날짜(한국 시간). 최근 14일 | 날짜 오름차순 |
| 고객사 | `A50:D60` (10행) | 통화 대장에 나온 고객사 | 불만이 많은 순. 같으면 통화가 많은 순, 그래도 같으면 먼저 나온 순 **(제안. 웹과 맞출지는 13장 6번)** |

- 목록이 비는 행은 값도 빈칸이다.
- 계산용 칸은 요약 시트 `J:T`열에 있고 숨겨 두었다. 고유한 이름을 뽑는 칸은 배열 수식이다. 고치지 않는다.
- 차트 3개(일자별, 담당자별, 고객사별)의 범위는 요약 시트에 정의한 이름 11개(`chtAgentA`, `chtDateA`, `chtCompA` 등)를 가리킨다. 이름은 값이 있는 행까지만 잡으므로 차트에 빈 자리가 생기지 않는다.
- 지표 6개, 유형별 표, 대시보드의 배치, 통화 대장의 표·서식·목록 제한은 원본 그대로다.

### 확인한 것

봇처럼 통화 대장만 다시 쓰고 수식을 재계산해 요약 시트를 읽었다(LibreOffice). 차트가 열리는지는 주영이 Excel에서 확인했다(11/23, 복구 메시지 없이 열리고 빈 자리 없이 보임).

| 넣은 데이터 | 결과 |
|---|---|
| seed 14건 | 지표 14 / 6 / 2 / 3 / 21% / 질의. 세 블록의 합 모두 14 |
| seed 14건 + 경계 사례 6건 | 지표 20 / 8 / 3 / 4 / 20% / 질의. 세 블록의 합 모두 20. `미확인`, 새 담당자, 새 고객사, 11-24가 목록에 들어온다. |
| 0건 | 오류 칸 없음. 지표는 0, 목록은 비어 있다. |
| 한도 초과(담당자 14명, 날짜 18일, 고객사 13곳, 120건) | 오류 칸 없음. 상위 10명, 최근 14일, 상위 10곳만 보여 준다. |

### 한계

- 담당자 10명, 날짜 14일, 고객사 10곳을 넘으면 넘는 만큼은 블록에 나오지 않아 블록의 합이 분석된 통화보다 작다. 지표 6개와 유형별 표는 영향이 없다.
- 요약 시트의 수식은 통화 대장 999건까지만 센다.
- 0건일 때 "가장 많은 유형"은 원본과 같이 `질의`로 나온다.

### 슬라이서

- 템플릿 v3에 슬라이서(담당자, 유형)를 넣어 저장했다. 통화 대장 시트의 표 오른쪽에 있다. 봇이 통화 대장을 다시 써도 남는다.
- **한계**: 표 슬라이서는 통화 대장의 행을 거를 뿐이다. 요약 시트의 수식은 숨겨진 행도 세므로 대시보드의 숫자와 차트는 슬라이서를 눌러도 바뀌지 않는다. MVP에서는 그대로 둔다.

### 템플릿을 다시 만들 때

저장소 `rpa-report/tools/`의 스크립트로 원본에서 다시 만들고 확인할 수 있다.

```
python tools/build_template.py templates/콜센터_엑셀_최종본_MVP.xlsx 결과.xlsx --dynamic
python tools/check_template.py 결과.xlsx out testdata/mock_calls_seed14_v1.json testdata/mock_calls_edge_v1.json
```

스크립트로 다시 만들면 Excel에서 넣은 슬라이서는 없어진다. 다시 넣는다.

## 8. 예외 처리

| 상황 | 처리 |
|---|---|
| 실패로 저장된 통화(`FAILED`) | 목록 조회가 완료 건만 받으므로 엑셀에는 들어가지 않는다. |
| 서버에 연결되지 않는다 | 3회 재시도 후 실패로 끝낸다. 기존 엑셀은 그대로 둔다. |
| 완료 통화가 0건이다 | 머리글만 있는 대장으로 저장한다. 지표는 0, 불만 비율은 0% |
| 출력 파일이 열려 있다 | 다른 이름으로 저장하고 경고 로그 |
| `called_at`을 날짜로 바꾸지 못한다 | 그 행의 B열을 비우고 경고 로그. 나머지 행은 계속 쓴다. |
| 녹음 파일명이 규칙과 달랐던 통화 | ③이 담당자와 고객사를 `미확인`으로, 통화일시를 파일 수정 시각으로 보낸다. 엑셀에는 서버 값 그대로 쓴다. 담당자 목록에 `미확인`이 한 줄로 나온다. |
| 통화가 999건을 넘는다 | 최신 999건만 쓰고 경고 로그 |
| 서버가 422를 돌려준다 | 재시도하지 않고 실패로 끝낸다. |
| 스크립트를 실행하지 못한다 | 종료 코드 1로 처리한다. |
| 스크립트의 종료 코드가 0이 아니다 | `Main.xaml`이 예외를 던져 Job이 실패(Faulted)로 끝난다. Orchestrator의 Jobs 화면에 남고, 다음 주기에 다시 시도한다. |

로그에는 통화 내용, 전화번호, 서버 주소 밖의 설정값을 쓰지 않는다. 관리번호와 건수만 남긴다.

## 10. 구성

저장소 `rpa-report/` 폴더가 UiPath 프로젝트다.

| 파일 | 하는 일 |
|---|---|
| `Main.xaml` | 시퀀스 3개다. (1) 서버 주소 읽기: Asset 2개에서 서버 주소와 API 키를 읽는다. (2) 엑셀 다시 만들기: 스크립트를 실행한다. (3) 결과 확인: 스크립트의 로그를 남기고 종료 코드가 0이 아니면 예외를 던진다. 인자는 없다. 시퀀스마다 쓰는 파일과 하는 일을 주석으로 달았다. |
| `build_report.ps1` | 서버 목록을 끝까지 받아(재시도 포함) 통화일시 순으로 정렬하고, 템플릿 복사본의 통화 대장을 다시 써서 저장한다. 종료 코드 0은 저장 성공, 1은 실패다. |
| `config.json` | 템플릿과 출력 경로, 쪽 크기, 재시도 횟수(3장). 커밋하지 않는다. |
| `tools/check_report.ps1` | 가짜 JSON으로 스크립트를 돌리고 결과 엑셀을 11장의 기대값과 비교한다. |

- 엑셀 쓰기를 워크플로우가 아니라 스크립트로 둔 것은 UiPath Studio가 없는 PC에서도 가짜 JSON으로 끝까지 시험할 수 있어서다. 스크립트도 Excel 프로그램으로 템플릿을 열어 쓰므로 차트와 슬라이서가 남는다.
- 스크립트는 `-BaseUrl` 대신 `-MockJson`에 가짜 JSON 파일을 주면 서버 없이 엑셀을 만든다.
- 두 스크립트는 ASCII로만 쓴다. Windows PowerShell 5.1이 BOM 없는 UTF-8 스크립트의 한글을 잘못 읽는다.
- 서버 주소와 API 키는 `Main.xaml`이 Asset에서 읽어 스크립트의 인자로 넘긴다. API 키가 명령줄 인자로 넘어가므로, 서버가 키 확인을 켜면 넘기는 방법을 바꾼다.
- 만드는 순서와 명령은 `rpa-report/README.md`에 있다.

## 14. 다른 파트 문서가 ④에 묻는 것

프론트엔드 설계서 최신본 10장의 항목 가운데 ④가 물어볼 곳으로 적힌 것이다.

| 프론트 # | 질문 | ④의 답 |
|---|---|---|
| 5 | 업로드 후 자동으로 처리를 시작하는지, 웹에서 처리 시작을 눌러야 하는지 | 정해졌다(범수·민영·수창 회신, 11/23 17:13~17:16). 업로드만으로는 시작되지 않는다. 가져가기(`ORCH_ENABLED=false`)에서는 ③ 봇만 처리 시작 API를 부른다. Job 시작(`true`)에서는 웹이 "처리 시작" 버튼을 보여 주고 사용자가 누를 때 부르며, ③ 봇은 Job 인자로 음성을 받는다. Job 시작이 실제로 돌려면 ④의 무인 실행 설정(수 오전)이 끝나야 한다. |
| 6 | 폴더를 감시하는 봇이 웹에서 삭제한 통화를 다시 저장하지 않는지 | 폴더를 읽는 것은 ③ 봇이다. ③ v0.8에 따르면 처리한 음성을 `done/`이나 `failed/`로 옮기므로, 사람이 입력 폴더로 되돌리지 않는 한 다시 저장되지 않는다. ④ 엑셀에서는 다음에 다시 만들 때 삭제한 통화가 빠진다. |
| 8 | 웹 카드 6개를 엑셀 지표 6개와 같게 쓰는 데 동의하는지 | 동의. 엑셀 템플릿의 이름, 반올림, 동률 규칙이 웹 정의와 같다(5장). |
