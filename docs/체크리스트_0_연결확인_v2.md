근거: 통합본 10장, 백엔드 PRD 11절(인수 테스트), ③ 설계서 6.1, ④ 설계서 11장. 순서대로 확인하고, 막히면 그 줄에 원인과 담당자를 적는다.

## 1. 서버가 떠 있다 (범수, 민철)

- [ ] 서버 PC에서 `GET /health`가 정상이다.
- [ ] 봇 PC와 웹 개발 PC의 브라우저에서 `http://<서버 주소>:8000/docs`가 열린다.
- [ ] seed 적재 후 `GET /api/stats`: 전체 15, 분석 14, 후속조치 6, 검토 필요 2, 실패 1, 처리 중 0

안 열리면: 서버를 `--host 0.0.0.0`으로 띄웠는지, 방화벽이 8000번을 막는지, 같은 네트워크인지 본다.

## 2. Orchestrator가 준비됐다 (주영, 민영)

- [ ] `Shared` 폴더에서 ④의 시간 트리거(1분)가 켜져 있다. 큐는 쓰지 않는다(v2, 강사 피드백 11/24).
- [ ] Asset `BACKEND_BASE_URL`에 지금 서버 주소가 들어 있다.
- [ ] Asset `BACKEND_API_KEY`에 비어 있지 않은 값이 들어 있다.
- [ ] Asset `CLOVA_INVOKE_URL`, `CLOVA_SECRET_KEY`가 있다.

## 3. seed 데이터로 웹과 엑셀이 같다 (수창, 주영, 범수)

봇 연동과 상관없이 먼저 확인한다.

| 지표 | 기대값 | 웹 | 엑셀 |
|---|---|---|---|
| 분석된 통화 | 14 | | |
| 후속조치 필요 | 6 | | |
| AI 결과 검토 필요 | 2 | | |
| 불만 통화 | 3 | | |
| 불만 비율 | 21% | | |
| 가장 많은 유형 | 질의 | | |

- [ ] 유형별 건수가 같다: 질의 6, 불만 3, 건의 2, 교육 내용 2, 기타 문의 1
- [ ] 조건 없이 받은 서버 엑셀(API 7)과 ④ 엑셀의 통화 대장이 모두 14행(머리글 제외)이다.
- [ ] 고객사별 불만 건수 차트에서 불만 건수가 같은 고객사의 순서가 웹과 엑셀에서 같다(통합본 33번).

## 4. 녹음 1건이 끝까지 간다 (민영 → 범수 → 수창, 주영)

- [ ] 입력 폴더에 규칙에 맞는 이름의 음성 1개를 넣고 ③ 봇을 실행한다.
- [ ] ③ 봇이 `POST /api/calls`에서 201과 관리번호를 받는다.
- [ ] 웹 목록에 약 10초 안에 새 통화가 보인다. 상세에서 대화와 음성 인식 신뢰도가 보인다.
- [ ] ④ 봇의 다음 실행(1분 안)에 엑셀 통화 대장에 그 통화가 한 줄 늘고, 대시보드의 분석된 통화가 웹과 같다.
- [ ] 처리한 음성이 `done/`으로 옮겨졌다.

## 5. 어긋나는 경우 (민영, 범수, 주영)

- [ ] 같은 음성을 다시 처리하면 409다.
- [ ] 일부러 실패시킨 통화가 `FAILED`로 저장되고 엑셀에는 들어가지 않는다. 웹에는 실패 사유가 한글로 보인다.
- [ ] 웹에서 통화 1건을 수정하면 ④ 봇의 다음 실행(1분 안)에 엑셀에 반영된다.
- [ ] 대화에 넣은 가짜 전화번호와 이메일이 웹과 엑셀에서 마스킹되어 보인다.

## 6. 이 자리에서 정할 것

- [ ] CLOVA 응답에 신뢰도 값이 실제로 있는가. 검토 필요 기준 0.7을 그대로 둘 것인가(통합본 27번).
- [ ] 챗봇 화면 담당과 우선순위, AI 키(통합본 15번)
- [ ] 외부 앱의 Client ID와 Secret이 전달됐고 토큰이 발급되는가(통합본 30번).
