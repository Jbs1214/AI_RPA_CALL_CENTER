# frontend 지침 (초안)

담당자(수창, 성진)가 확인하고 고친다. 아래는 `docs/설계서_2_프론트엔드_v3.pdf`와 팀 결정에서 옮긴 규칙이다. 공통 규칙은 루트의 `CLAUDE.md`에 있다.

## 참고할 곳

- 화면 구성과 카드·차트 정의: 설계서 3장
- 호출하는 API와 응답 처리: 설계서 4장, `docs/설계서_1_백엔드_v2.pdf` 5장
- 타입: 설계서 5장
- 지표 정의(엑셀과 같아야 한다): `docs/제품요구사항정의서_v1.8.md` 8장

## 규칙

- 서버 호출은 `src/api/`에, 서버 응답 타입은 `src/types/`에만 둔다. 서버 필드 이름이 바뀌면 이 두 곳만 고친다.
- 챗봇은 `src/features/chat/` 안에서만 작업한다. 메인 쪽에는 `App.tsx`의 `ChatWidget` 한 줄만 둔다.
- 서버 주소는 `VITE_API_BASE_URL`로만 바꾼다. 코드에 주소를 직접 쓰지 않는다.
- 카드 6개의 이름과 계산은 통합본 8장과 같게 둔다. 불만 비율은 정수로 반올림하고, "가장 많은 유형"이 동률이면 유형 고정 순서에서 앞선 것을 고른다.
- `confidence`는 화면에 "음성 인식 신뢰도"로 표시한다.
- 목록과 통계는 약 10초마다 다시 불러온다. 브라우저 탭이 숨겨지면 멈춘다.
- "처리 시작" 버튼은 `GET /health`의 `orchestrator.enabled`가 `true`일 때만 보여 준다. 업로드 뒤 처리 시작 API를 자동으로 부르지 않는다.
- 수정은 바꾼 항목만 보낸다. 삭제는 "이 통화와 음성 파일이 함께 삭제되며 되돌릴 수 없습니다." 확인 창을 거친다.
- 실패 코드는 한글 문구로 바꿔 보여 주고, 모르는 코드는 그대로 보여 준다.
- 챗봇의 수정 제안은 사용자가 버튼을 눌렀을 때만 수정 API를 부른다. 적용된 조건(`query`)을 항상 보여 준다.
- 만들지 않는 것: 로그인, 실시간 푸시(SSE·WebSocket), 모바일 반응형, 다크 모드.
